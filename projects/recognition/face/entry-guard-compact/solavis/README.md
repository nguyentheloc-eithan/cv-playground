# Solavis cloud

Config-driven multi-tenant backend with two web apps: the **customer app** (`/`, customers run their own devices) and the **admin console** (`/admin`, the company's CRM/ERP: accounts, billing, support, inventory, staff roles).
Devices talk to `/device/v1`. A camera simulator (separate program) stands in for hardware.

## Run the demo (about 2 minutes)
```bash
venv/bin/pip install -r requirements.txt
venv/bin/python -m solavis.manage seed --package demo      # creates tables, plans, demo customers, staff, sample people
venv/bin/python -m solavis.manage run                      # cloud:      http://127.0.0.1:8100  (customer)  /admin (staff)
venv/bin/python -m solavis.sim --package demo              # simulator: http://127.0.0.1:8101
```
Demo logins and what to try are listed in `RUN.md`.
Reset: `python -m solavis.manage reset --yes` then seed again.

## Configuration (`solavis/config/*.yaml`)
| File | Controls |
|---|---|
| `server.yaml` | host, port, workers, environment, logging, docs, upload limit, background jobs |
| `database.yaml` | `driver: sqlite \| postgresql \| mysql`, connection, pool, or a full `url` |
| `storage.yaml` | snapshots on `local` disk or `s3` (AWS S3, R2, B2, MinIO) |
| `security.yaml` | secret key, sessions, cookie flags, password rules, login lockout, device keys |
| `notifications.yaml` | Telegram bot, signed webhook, minimum level |
| `recognition.yaml` | model files, accept/reject/watch-list thresholds, photo rules |
| `tamper.yaml` | tilt/heading limits, view-change threshold, which events lock, check-in period, service window |
| `tenancy.yaml` | trial days, grace period, retention days, user limit, claim-code prefix |
| `billing.yaml` | invoice prefix, due days, tax rate, seller and bank details, optional VietQR |
| `roles.yaml` | what each staff role (admin, sales, support, finance) may do |
| `plans.yaml` | plans (copied to the database when missing; admins then edit them in the console) |
| `packages/*.yaml` | seed packages: `demo`, `production`, or your own |

Use your own copy of the folder with `SOLAVIS_CONFIG_DIR=/path` (files missing there fall back to the defaults). Values accept `${ENV}` and `${ENV:-default}`.
A typo, wrong type, or unsafe production setting stops start-up with a clear message. Check with `python -m solavis.manage check-config`.

## Go to production
1. `cp .env.example .env`, fill secrets. Edit `deploy/config/*.yaml` (domain, database).
2. `docker compose up -d`, then `docker compose exec solavis python -m solavis.manage seed --package production`.
3. Put HTTPS (Caddy/nginx) in front and keep `cookie_secure: true`.
4. Backups: PostgreSQL dump + the snapshot storage.

## Not done yet (be aware)

- PostgreSQL/MySQL: schema is verified to compile; a run against real servers is still to do.
- Billing is manual: invoices are generated by staff and payments are recorded by hand (no bank-feed matching, no payment gateway, no PDF invoices, no e-invoice).
- No email sending (temporary passwords are shown on screen), no web push, no firmware.
- Login lockout is in memory (one server). Use Redis for several servers.
- Direct image upload (the plan's presigned upload links are a later step).
